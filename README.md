# IDX Financial Data Scraper

A Python pipeline for scraping and structuring quarterly financial reports of companies listed on the **Indonesia Stock Exchange (IDX)** into clean, analysis-ready CSV files. It can also download the original PDF financial statements.

The pipeline runs in three sequential stages:

1. **Master data sync** — pulls sector, industry, and outstanding share data for each ticker via `yfinance` and writes them to `emitens.csv`.
2. **Report scraping** — downloads the raw financial report archive for each ticker/year/quarter from IDX.
3. **Report parsing** — extracts key financial metrics from the downloaded reports according to a configurable taxonomy mapping, producing `financial_reports.csv`.

A separate **PDF mode** (`--pdf`) downloads the PDF financial statements only. See [Downloading PDF financial statements](#downloading-pdf-financial-statements).

## Project structure

```

│   ├── watchlist.csv          # tickers to process
│   ├── taxonomy.csv           # common term -> source tag mapping, per taxonomy_type

│   ├── financial_reports.csv  # generated by the parsing stage
│   ├── failed_downloads.csv   # generated when a download fails
│   ├── chrome_profile/        # dedicated Chrome profile used for downloading

├── model/
│   ├── master-data.py
│   ├── fetch_idx.py
│   └── arelle_loader.py
├── requirements.txt
└── run.py
```

## Installation

```bash
pip install -r requirements.txt
```

`requirements.txt`:

```
cloudscraper
requests
beautifulsoup4
lxml
yfinance
playwright
chromium
```

Downloading from IDX requires **Google Chrome** to be installed. `fetch_idx.py` starts a regular Chrome window with remote debugging enabled (using its own profile in `data/chrome_profile`) and downloads files from inside that browser session. If Chrome is not in a standard location, pass its path when running `fetch_idx.py` directly:

```bash
python model/fetch_idx.py --chrome-path "D:\path\to\chrome.exe"
```

IDX may show a Cloudflare verification. When prompted in the terminal, make sure the IDX website loads normally in the Chrome window, then press Enter. The clearance is kept as long as that Chrome window stays open.

## Usage

Run the full pipeline from the project root (the directory that contains `run.py`):

```bash
python run.py
```

This executes all three stages in order: master data sync → report scraping → report parsing.

## Skipping stages

| Flag | Effect |
|---|---|
| `--skip-master` | Skip the master data sync stage |
| `--skip-fetch` | Skip the report scraping stage |
| `--skip-parse` | Skip the report parsing stage |

Flags can be combined freely:

```bash
# Scrape and parse only, without syncing master data
python run.py --skip-master

# Re-parse already-downloaded reports only
python run.py --skip-master --skip-fetch

# Scrape only, without syncing master data or parsing
python run.py --skip-master --skip-parse
```

> **Note:** if `--skip-master` is used without `--skip-parse`, `run.py` checks that `data/emitens.csv` already exists before proceeding, and will raise an error asking you to run the master data stage first if it doesn't.

## Limiting the year range

Applies to the report scraping and parsing stages (the master data stage is unaffected, but accepts its own `--shares-start-year` when run directly):

```bash
python run.py --start-year 2023 --end-year 2026
```

Defaults: `--start-year 2023`, `--end-year <current year>`.

## Limiting tickers and periods

`--tickers` and `--periods` narrow down the report scraping stage. Tickers must also exist in `watchlist.csv`. Valid periods are `Q1`, `Q2`, `Q3`, and `FY`.

```bash
python run.py --skip-master --skip-parse --tickers AADI ARCI --periods Q1 Q2
```

> **Note:** these two flags only affect the download. The parsing stage still processes every XBRL file found in `data/XBRL`.

## Downloading PDF financial statements

Add `--pdf` to download the PDF financial statements instead of the XBRL archives:

```bash
python run.py --pdf --start-year 2026 --end-year 2026 --periods Q1
```

To download specific tickers only:

```bash
python run.py --pdf --start-year 2026 --end-year 2026 --periods Q1 --tickers AADI ARCI BRMS PSAB
```

In PDF mode:

- The master data and parsing stages are skipped automatically, since PDFs are not parsed.
- Files are saved to `data/FinancialStatement/{year}/{period}/`, for example `data/FinancialStatement/2026/Q1/FinancialStatement-2026-I-AADI.pdf`.
- Files that already exist are skipped, so an interrupted run can simply be started again.
- Filings that IDX has not published yet return HTTP 404 and are counted as "not found", not as errors.
- Failures are written to `data/failed_downloads.csv` with a reason prefixed by `pdf_`.

The period token in the file name follows IDX's naming pattern:

| Period | Token |
|---|---|
| `Q1` | `I` |
| `Q2` | `II` |
| `Q3` | `III` |
| `FY` | `Tahunan` |

> **Note:** if a filing exists on IDX but the script reports it as not found, open the filing in a browser, check the real file name, and adjust `PDF_PERIOD_TOKEN` in `model/fetch_idx.py`.

## Overriding data location

```bash
# Custom data directory (default: <run.py directory>/data)
python run.py --data-dir "D:\path\to\data"

# Custom watchlist file (default: <data-dir>/watchlist.csv)
python run.py --watchlist "D:\path\to\custom_watchlist.csv"
```

## Combining flags

All options can be combined as needed:

```bash
python run.py --skip-master --start-year 2024 --end-year 2026 --data-dir "D:\idx-data"
```

## Required input files

- **`data/watchlist.csv`** — requires a `ticker` column. Optional columns `priority`, `added_at`, and `is_processed` are supported by `fetch_idx.py` to control processing order and skip tickers that have already been completed.
- **`data/taxonomy.csv`** — requires `taxonomy_type`, `common_term`, and `xbrl_tag` columns. Any additional columns (e.g. `id`) are ignored.

## Output

- **`data/emitens.csv`** — issuer list with taxonomy type and outstanding shares
- **`data/XBRL/...`** — raw downloaded reports per ticker/year/quarter
- **`data/FinancialStatement/...`** — PDF financial statements per year/quarter (PDF mode only)
- **`data/financial_reports.csv`** — final output: financial metrics per ticker, year, and period
- **`data/failed_downloads.csv`** — log of tickers that failed to download (if any)

## Known limitations

- Reports for tickers under the `insurance` taxonomy type currently have partial field coverage — some balance-sheet metrics may fall back to generic tags and require verification.
- If a currency conversion module is not present, USD-denominated figures fall back to a fixed default exchange rate rather than a live rate.
- In PDF mode, only the `Q1` file name pattern (`I`) has been confirmed against IDX. The tokens for `Q2`, `Q3`, and `FY` follow the usual pattern and should be verified on the first run.
